Design Patterns Used

Gang of Four (GoF) architectural design patterns powering the store management engine

Factory Pattern

Creates different product objects.

Technical Implementation: Client layers delegate concrete instantiation to ProductFactory.createProduct(category, id, name, price, stock). The factory evaluates the category key and manufactures the corresponding subclass. 

// Factory pattern instantiation
const item = ProductFactory.createProduct(
  "food",
  "P001",
  "Pancit Canton",
  15,
  50
);
Subclasses Manufactured:
  • FoodProduct (Food & Snacks)
  • BeverageProduct (Beverages)
  • PersonalCareProduct (Personal Care)
  • HouseholdProduct (Household)
  • SchoolSupplyProduct (School & Office Supplies)

Singleton Pattern

Maintains one central inventory manager.

Technical Implementation: InventoryManager enforces a single memory instance via getInstance(). All application modules share this centralized reference to prevent data divergence. 

// Singleton access
const inventory = InventoryManager.getInstance();
const inventory2 = InventoryManager.getInstance();
console.log(inventory === inventory2); // true
Why Singleton is Essential:
  • Guarantees a single source of truth for stock counts across all views.
  • Prevents concurrent overselling between POS and Inventory tables.
  • Synchronizes restocking events immediately.

Strategy Pattern

Allows different discount strategies to be selected.

Technical Implementation: Encapsulates discount algorithms into interchangeable classes sharing the uniform calculateDiscount(amount) interface contract. 

// Dynamic strategy swapping
checkout.setDiscountStrategy(new StudentDiscountStrategy());
const discount = checkout.calculateDiscount(subtotal);
const finalTotal = checkout.calculateTotal();
Concrete Strategies:
  • RegularDiscountStrategy → 0% discount
  • StudentDiscountStrategy → 5% discount (amount * 0.05)
  • BulkDiscountStrategy → 10% discount (amount * 0.10)
